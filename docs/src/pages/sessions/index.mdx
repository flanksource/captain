# Sessions

This section is scaffolded for Claude and Codex history, live prompt run entries, session browser behavior, cost analysis, and change tracking.

## Estimated tool cost

In a session's transcript, open the three-dot menu and enable **Show estimated tool cost**. It is off by default. Each tool's summary line shows a compact estimated USD amount. Expand the tool row to see its token usage, reasoning tokens when available, and cache reads and writes in a footer beneath the details.

Claude and Codex use the same allocation and display:

- Claude usage belongs to a response ID. Content-block records sharing that ID are grouped, and repeated usage is counted once. Each subagent transcript has its own response groups.
- Codex cumulative usage is converted into request deltas and matched to the preceding batch of tool calls.
- A request's tokens and cost are shared equally across its native tool calls. Token rounding preserves the batch totals. Prose, narrative plans, tool results and synthetic transcript events receive no allocation.

These estimates include conversation context and the model output that generated the calls. The model reads tool results in subsequent requests, so an estimate does not measure the isolated cost of a tool's returned text. Calls without usage data show a dash with an **Estimate unavailable** label. When usage is available but the model has no catalog price, the breakdown keeps its token counts and shows **Cost unavailable**.

The CLI and session API include the same data. For example:

```sh
captain sessions get 01a10698-d1e2-7282-885f-6e6aa640a3ae --json --limit 0
```

Each priced tool part has an optional `estimatedCost` object. Its `cost` field is the canonical token and cost breakdown; `sharedCalls` is the number of calls sharing that model request. Provider adapters identify the request and normalize its usage before the shared allocator attaches this object, so consumers do not need provider-specific costing logic.
