# Prompt format

A `.prompt` file has YAML frontmatter followed by a Handlebars body. dotprompt owns the template render and the built-in `model`, `config`, `input`, and `output` keys. Captain then reads the same frontmatter a second time and decodes any spec-native keys into `ai.Request`.

## Roles

The rendered body is split with dotprompt role markers. Captain treats rendered body text as authoritative: role output replaces any `prompt.user` or `prompt.system` values supplied in frontmatter.

<CodeExample client:load language="yaml" title="Role-marked body" source={`
---
model: claude-sonnet-5
mode: cli
permissions:
  mode: default
---
{{role "system"}}
You are running on the Claude CLI. Keep the answer concise.
{{role "user"}}
Handle:
{{task}}
`} />

## Spec-native frontmatter

Spec fields use the same nested shape consumed by the runtime editor and providers. The file can express permissions, memory, budget, setup, and model details without a separate translation layer.

<CodeExample client:load language="yaml" title="Spec-native prompt options" source={`
---
model: claude-sonnet-4-6
config:
  maxOutputTokens: 1024
  temperature: 0.2
permissions:
  mode: acceptEdits
  presets:
    - edit
  tools:
    allow:
      - Read
      - Edit
  mcp:
    disabled: true
memory:
  skipUser: true
budget:
  maxTokens: 5000
  maxTurns: 3
---
{{role "system"}}
You are a careful refactoring assistant.
{{role "user"}}
Refactor:
{{target}}
`} />

## Runtime profile pin

`runtimeProfile` names a saved runtime profile by id or name. Rendering resolves the profile's presets (ordered by scope), then its spec, then this frontmatter, then the caller's request or CLI flags, so the file can defer model, budget, and permission defaults to a shared profile while still overriding any of them inline. A caller that passes `runtimeProfile` on the render request or `--runtime-profile` on the command line replaces the pin; a pin that names no profile in the catalog fails the render rather than silently running without it. The render result's `resolution.trace` lists every layer that contributed. Captain binaries older than this key reject a file that uses it.

<CodeExample client:load language="yaml" title="Pinned runtime profile" source={`
---
model: claude-sonnet-4-6
runtimeProfile: review
budget:
  maxTurns: 7
---
{{role "user"}}
Review the diff in {{path}}.
`} />

## Structured output

When no Go output target is passed to `Render`, Captain marshals a dotprompt `output.schema` into `Prompt.SchemaJSON` and sends it to the provider unchanged. A concrete Go output target takes precedence and is attached as `Prompt.Schema` for provider-side schema generation.
