# Todo execution

Gavel owns TODOs, their lifecycle, acceptance criteria, fixture verification and commit finalization. Captain owns prompt rendering, runtime resolution, provider execution, approvals, session recording and the generate/verify loop. Gavel embeds Captain through Go APIs; it does not require the `captain` CLI to dispatch a run. A selected runtime may launch its own agent CLI or use its API transport.

TODOs are PostgreSQL-backed issues. Markdown `.todos` files are portable import/export artifacts rather than the live store; grite and file-provider selection are no longer the runtime workflow.

## Typical flow

```sh
gavel todos list
gavel todos list --all --done
gavel todos get TODO_ID
gavel todos steps TODO_ID
gavel todos run TODO_ID --step plan
gavel todos plan approve TODO_ID
gavel todos run TODO_ID
gavel todos check TODO_ID
```

`run` requires explicit IDs. Without `--step`, it selects the next applicable lifecycle step; `steps` shows the available steps and where a TODO stands. Planning stores a durable Captain plan revision for human review. Implementation runs through Captain and Gavel verifies the persisted definition-of-done fixture before its post-verification commit step.

## Ownership

| Gavel | Captain |
| --- | --- |
| TODO body, priority, status, labels, parent and links | Resolved `api.Spec`, trace, provenance and warnings |
| Lifecycle selection and result predicates | Provider construction and execution admission |
| Fixture engine and CEL verification verdict | Verifier registry and progress/report transport |
| Commit gates, staging and issue/session trailers | Session, prompt-run, approval and plan storage |

The same `promptrun.Run` seam serves standalone prompt execution and an embedding host. Gavel supplies host hooks and commit ownership so one run cannot commit the same tree twice.
