# Execution and verification

Every project defines an ordered lifecycle. Its steps pair Captain prompts with CEL predicates that decide whether a step applies and how its result changes the TODO. The default lifecycle includes triage, plan, verify and run. Inspect the current project rather than assuming a fixed sequence.

```sh
gavel todos steps
gavel todos steps TODO_ID
gavel todos run TODO_ID --dry-run
gavel todos run TODO_ID --step plan
```

`--dry-run` prints the prompt and resolved spec without dispatching. `--preview` does dispatch an agent, but makes its TODO merge/close tools report their intended writes. These flags have different effects.

## Runtime selection

```sh
gavel todos run TODO_ID --model agent:sonnet:high
gavel todos run TODO_ID --preset Plan --step plan
gavel todos run TODO_ID --resume
```

`--model` accepts `mode:model:effort`; there is no separate `--driver` flag. `--preset` layers reusable runtime presets and `--no-presets` clears prompt/project defaults. `--max-budget` and `--max-turns` supply run limits. Captain validates the resolved runtime, capabilities, approval wiring and timeout before dispatch.

`--dirty` carries uncommitted and ignored content into a new worktree. It does not mean discarding existing changes or running directly over a dirty source tree. `--reuse-branch` continues the branch left by one TODO's previous run; `--resume` continues its prior agent session. `--commit=false` disables lifecycle-step commits when intentionally requested.

## Plan review

```sh
gavel todos plan approve TODO_ID
gavel todos plan approve TODO_ID --run
gavel todos plan reject TODO_ID
gavel todos plan revise TODO_ID --feedback 'Separate schema and data migration'
gavel todos plan recover TODO_ID
```

Approve selects the reviewed revision for implementation; `--run` chains execution. Reject preserves history and removes the active selection. Revise runs an agent with feedback and returns the updated plan for review. Recover backfills the plan from the latest terminal plan-step run; use `gavel todos edit --plan` to supply one directly.

## Definition of done

```sh
gavel todos criteria TODO_ID
gavel todos check TODO_ID
gavel todos check TODO_ID --timeout 10m
```

The persisted Gavel fixture is the verification authority. It runs checks, produces test results, and evaluates its CEL verdict. An AI acceptance review, when configured, is part of that fixture rather than a separate `todos verify` command. A failed fixture supplies feedback to the execution loop; it cannot be replaced by a successful prose summary.

Gavel owns post-verification commits, including staging, gates and session/issue trailers. Captain receives host commit hooks with `CallerOwnsCommits` so its workflow does not create an additional commit. Use `gavel todos get TODO_ID` for persisted plan, run and verification history.
