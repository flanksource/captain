# Adapter and resource schemas

Open `/adapter-schemas` in `captain serve --dev`. Select a provider and resource to inspect its schema or edit a local Form, JSON or YAML draft. Resource selection, view and search are shareable URLs; draft values remain in the mounted page and are discarded on reload. Switching resources retains each draft. Invalid JSON/YAML stays editable and disables form editing and validation until corrected.

“Validate schema” checks the document against its selected JSON Schema. It does not resolve profile inheritance, inspect credential files, check installed tools, enforce runtime capabilities, execute hooks or apply configuration. Execution-only managed/unsupported options and enrollment-managed agent records render read-only. Native resource schemas describe the provider's configuration independently of Captain's forwarding support.

## Catalog

The page combines two catalogs of documents with stable `id`, `kind`, `provider`, `title`, `description` and `schema` fields; execution documents additionally carry `mode`.

- `GET /api/captain/ai/adapter-schemas` returns the schemas embedded in the Captain binary: execution schemas (`anthropic/api`, `openai/agent`, …) and Captain's own resources (`captain/permissions`, `captain/preset`, `captain/docker-backend`, `captain/git-agent-backend`, …).
- Native provider resources (`openai/permission-profile`, `anthropic/sandbox`, `google/settings`, …) are not embedded. The browser loads them from the published catalog at `https://raw.githubusercontent.com/flanksource/captain/schemas/adapters/native-resources.json`. When that fetch fails, the page reports the URL and status and keeps the embedded schemas usable. Build the web app with `VITE_CAPTAIN_NATIVE_RESOURCES_URL` set to point it at another catalog, such as one generated locally.

POST a value without saving or applying it. An embedded document is looked up by `id`. A published document is not known to the server, so the request carries its `schema`:

```sh
curl -sS http://localhost:9020/api/captain/ai/adapter-schemas/validate \
  -H 'Content-Type: application/json' \
  -d '{"id":"captain/permissions","value":{"mode":"plan","tools":{"Bash":"deny"}}}'
```

Errors include JSON-pointer instance and schema paths. A well-formed request with invalid values returns HTTP 200 and `valid:false`. Malformed requests and uncompilable carried schemas return 400, unknown embedded IDs 404, and invalid embedded schemas 500. A carried schema must be self-contained: external `$ref`s are never loaded. The endpoint has a 16 MiB request limit, which fits the largest carried schema. No runtime or persistence call occurs.

## Sources and regeneration

Configuration snapshots record source versions, references, SHA-256 and top-level property counts in `x-captain-resource`. Execution schemas retain `x-captain-adapter` provenance, support annotations and source inventories. CLI inventories include every long option in the captured execution command help, including aliases. API inventories follow the module-pinned request types and nested definitions, preserving required fields, literal discriminators, native enums and typed maps.

### Native resources: generated by CI, published to the `schemas` branch

The `Adapter schemas` workflow (`.github/workflows/adapter-schemas.yml`) runs on pull requests that touch `hack/adapterresources` or `pkg/adapters`, and on `main`:

1. `hack/adapterresources/fetch-sources.sh` captures the pinned sources into `.tmp/adapter-schema-sources`: the Codex and Gemini release configuration schemas, and the Claude settings, agent, MCP and plugin schemas that `ts-json-schema-generator` derives from the `@anthropic-ai/claude-agent-sdk` type declarations (`hack/adapterresources/claude-types.ts`).
2. `go run ./hack/adapterresources resources -out .tmp/adapter-schemas` applies the patches, annotates the schemas for forms, and writes `<provider>.json` plus `native-resources.json`, the catalog projected by `adapters.NativeResourceSchemas`.
3. `go test -tags adapterresources ./pkg/adapters` with `CAPTAIN_ADAPTER_RESOURCES=.tmp/adapter-schemas` checks the generated catalog: every projection is present and annotated, native examples validate, and the patches took effect. Without the variable these specs fail rather than skip.
4. On `main` only, `hack/adapterresources/publish-schemas-branch.sh` commits the output to `adapters/` on the orphan `schemas` branch. The branch holds only generated artifacts. The first run creates it, and an unchanged output publishes nothing.

`task schemas:generate` runs steps 1–3 locally. It needs `curl`, Node.js and Go.

#### Patches

`hack/adapterresources/patches/<provider>.yaml` corrects upstream help text, typing and enums declaratively, as an RFC 6902 JSON Patch authored in YAML. A provider's patch file is named in `nativeSources` (`hack/adapterresources/main.go`). Patches apply to the source as captured, before root flattening, so a change to a definition reaches every projection of it. Put a `test` op before each change that depends on an upstream value. If the SDK changes that value, generation fails instead of silently patching something else. Never edit generated output by hand.

### Execution schemas: committed

The execution schemas under `pkg/adapters/<provider>/` are committed and embedded. Enriching them needs locally installed CLIs (Claude CLI 2.1.309, Codex CLI 0.164.0 and Gemini CLI 0.64.0) and the generated native resources. Capture the CLI sources after `task schemas:generate`:

```sh
codex app-server generate-json-schema --experimental --out .tmp/adapter-schema-sources/codex-protocol
claude --help > .tmp/adapter-schema-sources/claude-help.txt
codex exec --help > .tmp/adapter-schema-sources/codex-help.txt
gemini --help > .tmp/adapter-schema-sources/gemini-help.txt
go run ./hack/adapterresources execution -resources .tmp/adapter-schemas
go generate ./pkg/adapters
```

Then run `gavel test ./pkg/adapters`. Review source-version changes deliberately. The importer rejects missing native root shapes and newly uncovered CLI flags. Codex's generated schema omits `serde(flatten)` permission maps; their value schemas are supplied from `codex-rs/config/src/permissions_toml.rs` at the same release, with source references on each supplemented definition.

Captain backend JSON follows `sandbox.backends.<name>` in `~/.captain.yaml`: `kind` and backend option keys are siblings. Docker backend volume values are strings (`source:target[:ro]`), distinct from the structured volumes in `.container-sandbox.yaml`. Git Agent enrollment entries contain endpoint trust and credential **paths**, never credential contents. Its `waitTimeout` remains subject to positive-duration validation at runtime.

## Form annotations

Use `title`, `description`, `x-help.links`, `x-clicky-order`, `x-clicky-section`, `x-enum-labels`, `x-enum-display`, `x-enum-icons`, `x-array-display` and `readOnly` on the owning schema nodes. Documentation links are absolute HTTP(S) URLs. Icons resolve through Clicky UI's offline icon provider. Presentation annotations do not replace validation constraints or native wire names.

Clicky UI renders object/array/scalar unions with a branch selector and retains branch drafts. `format:json` explicitly requests a typed JSON editor for genuinely arbitrary JSON. Typed `additionalProperties` and `patternProperties` remain editable maps; recursive references are kept in the schema graph rather than expanded indefinitely. Native source schemas can evolve independently of Captain's executable option coverage.

## Live form smoke check

With the development server on port 9020, run `go run ./hack/adapterbrowser`. It uses `agent-browser --engine chrome --session captain-adapters-impl` to open every document of the embedded catalog and of the published native catalog (`-native-catalog` overrides its URL) in Form view, verifies the local-preview and validation controls, and fails on a render error. It does not change resource values or apply configuration. Close that browser session after inspection with `agent-browser --engine chrome --session captain-adapters-impl close`.

The expansion was checked against all 50 live form views, JSON/YAML draft retention and correction, server-side nested permission errors, documentation links and offline enum icons, plus desktop and 390px compact layouts. Focused Go contract/API tests, 485 shared form tests, Captain UI tests, scoped lint, Go and Clicky builds, and repeated-generation hashes passed. Repository-wide lint encounters unrelated duplicate `main` declarations under `hack/`; the production webapp build encounters the existing `RuntimePreset.order` mismatch with the pinned published Clicky package. The shared form improvements live in the sibling Clicky UI checkout and need its normal release/dependency update before shipping.
